# Agentic Programming as Formal Automata: A Chomsky-Hierarchy View of Tool-Using LLM Agents

**Author:** Scott Weeden

## Abstract

We propose a unifying vocabulary in which *agentic programs*—policies that interleave observation, reasoning, and tool invocation—are classified by the same structural constraints that separate finite automata, pushdown automata, linear-bounded automata, and Turing machines in the Chomsky hierarchy. Rather than claiming that LLM agents literally implement any one grammar, we define the *trace languages* generated by agent schemata and show how restrictions on control-state cardinality, auxiliary memory, and growth of workspace relative to interaction length yield a four-level taxonomy analogous to Types 3–0. The goal is to make informal claims about "bounded" versus "general" agent stacks, memory, and planning depth formally comparable to classical automata theory, supporting reproducible evaluation design and peer critique.

## 1. Introduction

Software systems that combine large language models (LLMs) with tools, retrieval, and multi-step control flow are often described as *agentic*: they repeatedly observe an environment, update internal state, and emit actions until a termination condition holds. The Chomsky hierarchy partitions formal languages by generative power and, equivalently, by the automaton class needed to recognize them.

This paper does **not** assert that a deployed LLM instantiates a particular grammar on natural language. Instead, we treat an *agentic program* as a specified controller whose *interaction traces* form a formal language over finite grammars of observable events. Restrictions on that controller's state space and memory discipline yield a hierarchy of trace languages that parallels Types 3–0.

## 2. Agent Schemata and Transition Systems

### Workspace

A *workspace* is a structure W equipped with a size function and an update operator. Examples: (i) a finite register file; (ii) a stack of pending subgoals; (iii) a tape of length f(n) after n steps; (iv) read/write access to an unbounded external store.

### Agent schema

An *agent schema* is a tuple A = (S, s₀, W₀, Σ_obs, Γ_act, δ, F) where:

- S is a finite set of *modes*
- s₀ ∈ S is the initial mode
- W₀ is the initial workspace
- Σ_obs and Γ_act are finite observation and action terminal sets
- F ⊆ S × W is a set of accepting configurations
- δ : S × W × Σ_obs → P_fin(S × W × Γ_act*) is a transition rule

### Run and trace language

A *run* produces a *trace* (o₁,a₁)…(o_n,a_n). The *trace language* L(A) is the set of traces of accepting runs under a fixed termination rule.

## 3. Four-Level Hierarchy

| Class | Name | Memory pattern | Agent interpretation |
|-------|------|----------------|----------------------|
| Type-3 | Regular | Finite workspace, bounded independent of n | FSM-wrapped LLM, Markovian controllers |
| Type-2 | Pushdown | Stack over finite stack terminals | Nested subgoals, hierarchical ReAct |
| Type-1 | Linear-bounded | ‖W‖ ≤ cn + c₀ | Full transcript in scratch, linear growth |
| Type-0 | Turing | Unbounded external store | Files, vector DBs, subprocess+HTTP envelopes |

**Shortcuts and strategies:** Deployed Type-0 agents use external stores E with retrieval morphisms mapping history to compact handles.

## 4. Evaluation and Pre-Registration

Separate *claims* about computational class from *evidence*:

1. **Control-state audit:** bound |S| (explicit modes in code)
2. **Memory audit:** classify W as finite, stack-structured, linear, or unbounded external
3. **Trace logging:** record (o_i, a_i) under fixed discretization; hash secrets

Pre-register: (i) trace encoding, (ii) claimed class, (iii) stopping rules and primary metrics.

## 5. R&D Bayesian Loop Agent Model

Multi-agent MLE pipelines (e.g., Kaggle competitions) instantiate swim-lane trace languages: each column is an agent role; each row is a discrete capability token or CLI command. Governance rows encode dependency graphs (`add_task`, `add_dep`, `topological_order`, `dispatch`).
